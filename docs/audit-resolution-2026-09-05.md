# 项目审计处理记录

处理日期：2026-09-04 至 2026-09-05。

## 已确认的产品决策

项目负责人已明确接受以下三项，后续审计不得在实现未发生实质变化时再次作为缺陷提出：

1. 自启动计划任务使用最高可用权限，并向 Everyone 授予完全控制。
2. CLI 静默卸载默认删除截图、录屏及个人数据，保留数据需显式指定参数。
3. QuickLook 可保留音视频及 PDF 格式声明，相关内联预览暂不实现。

这些决策同步记录在 `.agents/rules/agent.md` 和 `HANDOVER.md`。

## 修复结果

| 项目 | 本轮处理 |
| --- | --- |
| 搜索服务生命周期 | Windows 服务为 `DEMAND_START`；应用启动、隐藏 WebView 预载、设置状态查询和退出不启动服务。用户首次通过快捷键、托盘、设置按钮或 `--show-search` 打开搜索时启动；此后跨搜索窗口隐藏和 Tools3000 退出常驻，直到 Windows 关机/重启或管理员停止。 |
| 覆盖率要求 | 全库 100% 要求改为 32% 原生行覆盖率基线与针对性回归测试；实测提高后逐步上调。显式 `-Coverage` 缺少工具、报告或测试程序时失败；不再静默跳过。 |
| Lua 文件权限边界 | 完成评估，运行时行为保持不变。定位为可信本地自动化环境，不能宣称可隔离不可信代码，详见 `lua-security-model.md`。 |
| 原生重命名 | 统一为同父目录的单文件名重命名，拒绝路径逃逸、绝对路径、NTFS 数据流、设备保留名和非法结尾；目标已存在时不覆盖。 |
| 构建脚本 | x64/ARM64 使用独立构建目录及匹配的工具链、运行库和产物架构校验；固定 vcpkg 提交，干净环境默认使用用户可写目录。两个入口共用 WebView2 恢复脚本，下载固定版本并验证锁定的 SHA-256，不再依赖本机残留 NuGet 客户端。 |
| 发布供应链 | 正式发布执行自有二进制、安装器及卸载器签名门禁；标签与 Release 资产不可覆盖；切换已有开发分支采用合并，避免重置分支。 |
| 许可材料 | 随包生成第三方许可正文和 SPDX SBOM；补入 npm 包许可与字体许可，并校验内嵌字体的来源哈希。 |
| 核心文件与重复实现 | 从 MessageBridge 和 SearchPlugin 拆出文件、系统及搜索窗口交互处理器；重命名共用 PathOperations。两个发布入口共用目录清理策略。 |
| 未使用 Watchdog | 删除未被应用启动或发行包使用的独立 Watchdog 源码与构建目标；该旧实现会按进程名定期强制修剪工作集。源码可从 Git 历史恢复。 |

重构按职责和行为一致性拆分。截图输入、渲染等较大的状态化模块，以及生成的数据表，本轮未按行数机械拆分。

## 验证边界

- 本机缺少 MSVC ARM64 工作负载，ARM64 完整编译与目标机运行仍需在配置好工具链的环境完成；脚本必须清晰报错，不能把 x64 产物标成 ARM64。
- 正式 Authenticode 签名需要项目自己的有效证书。本轮验证签名门禁与拒绝路径，未使用临时证书冒充正式签名。
- 本轮没有推送 Git、创建 Release 或替换本机已安装版本。
