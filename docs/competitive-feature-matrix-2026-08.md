## 1. 阅读说明与证据口径

这七款产品并非完全同类：Everything 和 Listary 主攻搜索；PixPin、Snipaste 主攻截图贴图；WGestures 2 主攻鼠标手势；FocuSee 主攻自动后期录屏；Tools3000 是 Windows 原生效率工具集。因此，“—”通常表示不属于产品定位，不能简单理解为产品质量较差。

标记含义：

| 标记 | 含义 |
|---|---|
| ✓ | 在本次核对版本中，由官方资料或 Tools3000 当前代码明确确认 |
| ◐ | 部分支持、需要间接操作，或能力范围明显受限 |
| P | 付费版、会员版或 Pro 专属 |
| B | Beta/测试版能力，不应宣传为稳定版能力 |
| P/B | 付费且仍处于 Beta/伴生产品集成阶段 |
| — | 官方资料未将其作为产品能力，或明显不属于该产品范围 |
| ? | 公开资料不足，暂不作肯定或否定结论 |

严谨性规则：

1. 不把路线图、预告、插件市场占位或第三方脚本当作已经交付的原生能力。
2. 免费版和付费版分开标注；不能用 Pro 功能代表免费版。
3. “支持 4K”“硬件编码”“低内存”等性能型结论，必须附带硬件、编码器和工作负载条件，不使用“零延迟”“完美支持”等绝对措辞。
4. Tools3000 以项目版本 v1.0.0、`main` 分支 HEAD `b1d5aa446412` 为本次源码基线；README 与代码不一致时，以可执行代码路径为准。未发布的工作树改动不能据此宣传为已发布版本能力。
5. 表格按用户可感知的能力粒度统计，不细拆每个颜色、快捷键或搜索函数，因此是“全面功能清单”，不是每个设置项的穷举。
6. 所有版本号与功能判断只对统计截止日期有效；后续产品更新必须建立新快照，不能直接用新版结论覆盖本版历史数据。

### 搜索赛道结论

- Everything 仍是纯文件索引、搜索语法、属性搜索、重复文件、CLI/SDK 和网络索引能力的标杆。
- Listary 的核心差异不是“比 Everything 搜得更多”，而是把文件、应用启动和打开/保存对话框连接起来。V7 的多选、日期/大小语法和预览增强截至基准日仍是 Beta。
- Tools3000 已经具备 MFT、拼音、正则、内容摘要、运行/搜索历史和文件对话框增强，但在 ReFS、NAS、属性索引、重复文件、批量操作、统一应用启动器方面落后于对应标杆。

### 录屏赛道结论

- FocuSee 的优势是“录完自动成为适合发布的视频”，而不是截图或系统工具；自动缩放、光标、字幕、静音删除、音频增强、摄像头布局和社媒导出形成完整后期链路。
- PixPin 的录屏更接近截图工作流的延伸，适合快速 GIF/WebP/MP4 演示；其 Pro 版提供键鼠显示和录后裁剪。
- Tools3000 的优势是本地格式、双通道音频、实时诊断和与截图/手势/Keycast 联动；当前缺少摄像头、时间线编辑、自动运镜和字幕。

- “Tools3000 搜索支持 NTFS 文件索引、拼音、通配符、正则、路径与内容检索；它当前不能替代 Everything 1.5 的 ReFS、网络索引、属性索引和重复文件能力。”
