# Lua 安全模型评估

评估日期：2026-09-04

## 结论

Tools3000 的 Lua 运行环境定位为**用户本机可信自动化脚本环境**，不是用于执行不可信代码的操作系统级安全边界。当前实现保留脚本开发与自动化所需的能力，本轮不改变运行时行为。

## 当前边界

- 未开放 `io`、`debug`、`package`，因此脚本不能直接使用这些标准库或动态加载 C 模块。
- `os.execute`、`os.remove`、`os.rename`、`os.exit`、`os.tmpname` 和 `os.setlocale` 已移除。
- `easy.*` 中键鼠、窗口、剪贴板、屏幕、进程、文件和网络等敏感能力受声明权限与用户授权控制。
- 执行器提供超时和取消检查，降低脚本失控对应用进程的影响。

## 已知限制

Lua `base` 库仍包含 `dofile` 和 `loadfile`，受限的 `os` 库仍包含 `os.getenv`。因此，即使脚本没有申请 `easy.fs` 权限，它仍可能读取本机可访问的 Lua 文件或环境变量。权限系统约束的是 `easy.*` API，不构成 Windows 文件系统、注册表、网络或进程权限的完整隔离。

基于以上限制，以下来源的脚本不应直接运行：

- 未审查的网络下载脚本；
- 来历不明的社区脚本；
- 由不可信输入动态拼接或生成的脚本。

## 后续可选方案

如果未来需要运行第三方脚本，应新增与现有模式并存的“受限模式”，至少移除 `dofile`、`loadfile`、`load` 和 `os.getenv`，按脚本建立独立状态，并通过受控虚拟文件系统提供显式授权的文件访问。现有“可信自动化模式”可保留，以免破坏复杂本地自动化工作流。
